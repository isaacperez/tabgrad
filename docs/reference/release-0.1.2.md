# Tabgrad 0.1.2 source and support record

This record identifies ordinary `@tabgrad/tabgrad@0.1.2`, selected npm channel
`latest` and repository tag `v0.1.2`, under the [release policy](../releases.md).
Source metadata does not establish registry availability or a successful CI
publication. The actual release evidence identifies its source revision,
archive/inventory, original producer proofs and delivery outcome.

## Maintainer changes

[The publication correction](https://github.com/isaacperez/tabgrad/pull/376)
keeps consumer verification and GitHub completion eligible when the unused
authentication branch is skipped. Successful prerequisites and cancellation
checks still govern each stage. Actual job execution must be inspected; a
successful source test or aggregate workflow result alone is insufficient.

[The laboratory retirement](https://github.com/isaacperez/tabgrad/issues/377)
removes the superseded experimental native acquisition tools, their commands,
tests, fixtures and reference contracts. Reference navigation separates
application interfaces from maintainer tools. The active hosted producer,
proof verifier, publisher and release recorder remain in place; their current
commands are in the [publication procedure](release-publication.md).

## Preserved support and qualification

The [0.1.1 support record](release-0.1.1.md), including its inherited
[0.1.0 API-group table](release-0.1.0.md), applies unchanged: the same tensor
calls, numerical contracts, errors, warnings, identity, aliases, gradients,
partial progress, float32/layout/device limits and declared environments.
PyTorch support remains **Partially supported**. No operation, dtype, gradient
mode or browser/device support is added. Runtime, Python, kernel, conformance,
dependency and build inputs are unchanged from the identified 0.1.1 source;
reused observations retain their original revision and scope.

The changed metadata and packaged guide require a new exact candidate.
Its source PR records the archive/inventory and installed public-entry/static
byte checks, six Chrome/Firefox CPU profiles and two physical GPU/origin
profiles. Those reports identify the actual environments, adapter and cleanup
limits; they do not establish general hardware coverage or a speed/memory bound.
The protected-main producer must separately qualify and sign its own retained
bytes. Registry consumers and the completed CI flow are later delivery evidence;
earlier artifacts, proofs or skipped jobs cannot be relabelled as that execution.

## Maintenance and updating

When admitted as the latest ordinary release, `0.1.2` supersedes `0.1.1` under
the existing default-branch maintenance policy. Earlier version records remain
historical; no backport branch, LTS promise or new grace period is introduced.

Applications need no tensor API migration. Install the exact verified version
and replace the complete matching static asset tree under the existing
[installation and ownership contract](browser-package.md). Contributors using
the removed experimental commands can inspect their historical source in Git;
they are no longer maintained entry points. No native experiment is needed to
use or publish this version.
